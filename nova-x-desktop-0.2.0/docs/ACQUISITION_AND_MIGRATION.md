# DEV — Autonomous Software Acquisition, Environment Management, and Universal Migration Engine (§221–§235)

This subsystem enables DEV to discover, verify, install, configure, test, and manage missing software and complete isolated project environments under standing operator policies—and to package, verify, transfer, and hardware-adaptively restore a complete DEV portable identity across compatible Linux/Kali machines (`PlatformService.acquisition_migration`, `DesktopRuntime.acquisition_migration`, `ToolRegistry`, `CapabilityRegistry`, `nova-x acquire`, `nova-x migrate`, `NovaWindow`, and `/api/acquisition/*` + `/api/migration/*`).

## Section-by-Section Architecture

| Section | Module / Class | Verified Capabilities & Safety Controls |
| --- | --- | --- |
| **§221–§222** | `IntelligentSoftwareDiscoveryEngine` (`discovery_and_provenance.py`) | Covers 22 software acquisition categories across a 15-step discovery pipeline. Checks DEV's managed inventory, `PATH`, and Debian/Kali alternate binary names (`batcat`, `fdfind`, `python3`, `nodejs`, `7zz`, `ncat`) before downloading anything, compares alternatives, evaluates Kali/RAM/disk compatibility, and selects a single optimal option without installing overlapping duplicates. |
| **§223** | `UniversalPackageManagerDiscovery` (`discovery_and_provenance.py`) | Probes actually installed package managers across 7 ecosystems (`kali_and_debian`, `python`, `javascript_nodejs`, `other_dev_environments`, `desktop_applications`, `containers`, `source_distributions`) without assuming availability or mutating `/etc/apt/sources.list*`, and blocks arbitrary `curl \| sudo bash` commands. |
| **§224** | `AutomaticDependencyResolver` (`installer_lifecycle_env.py`) | Detects missing executables/modules and version conflicts, provisions isolated per-project `.dev_env` virtual environments without modifying global packages, locks resolved versions in `dev-requirements.lock.json`, and verifies imports in a clean subprocess. |
| **§225** | `SoftwareProvenanceVerifier` (`discovery_and_provenance.py`) | Evaluates 13 provenance fields across 5 trust tiers, verifies SHA-256 checksums and APT repository metadata, blocks blind root script execution, and quarantines unverified or checksum-mismatched artifacts (`0400` permissions in `workspace/quarantine/` + `software_quarantine_records`). |
| **§226** | `AutonomousInstallationController` (`installer_lifecycle_env.py`) | Enforces a 3-tier standing policy (`automatically_permitted`, `preauthorized_operations`, `restricted_operations`) configured once in SQLite; finishes unrelated work while reporting exact missing authorization when gated; refuses unapproved financial commitments (`ALLOW_UNAPPROVED_FINANCIAL_COMMITMENTS = False`); tests installed binaries (`--version`); and registers verified capabilities in `CapabilityRegistry`, `UniversalApplicationRegistry`, `ToolRegistry`, and `managed_software_inventory`. |
| **§227** | `SoftwareLifecycleManager` (`installer_lifecycle_env.py`) | Tracks 13 lifecycle attributes, generates software inventories, detects duplicate capabilities, never auto-removes software merely due to inactivity (`AUTO_REMOVE_UNUSED_SOFTWARE = False`), checks reverse dependents across apps and environment profiles before uninstall, and preserves configuration files by default. |
| **§228** | `AutonomousEnvironmentBuilder` (`installer_lifecycle_env.py`) | Executes all 12 steps to build complete isolated environments (`python_development`, `nodejs_react`, `cybersecurity_lab`, `3d_modelling`, `data_analysis`), runs live validation workflows, exports portable `env-profile.json` specs + `SETUP_INSTRUCTIONS.md`, and recreates environments on target machines (`recreate_environment_from_profile`). |
| **§229–§230** | `DevMigrationManager` & `UniversalMigrationArchiveCodec` (`migration_and_backup.py`, `crypto_and_archive.py`) | Exports selectable sections **A–F** (`core_data`, `memory_and_knowledge`, `ai_configuration`, `software_and_environments`, `projects_and_files`, `local_models`) in the versioned `nova-dev-migration-v1` compressed TAR format (`.tar.zst` / `.tar.xz` / `.tar.gz`) with per-file SHA-256 checksums, optional multi-volume splitting (`.part001`, `.part002`, ...), automatic exclusion of `node_modules`/`__pycache__`/`.venv` caches, and zero automatic cloud uploads. |
| **§231 & §233** | `DevMigrationManager` (`migration_and_backup.py`) | Compares 11 hardware/OS dimensions before restore, blocks overwriting target machine identity (`machine_id`, network interface names, drivers, boot configs), adapts memory/GPU concurrency on constrained hardware, builds storage-estimated offline kits preserving non-redistributable references for deferred online recreation, and supports checkpointed resumption of interrupted migrations. |
| **§232 & §234** | `OneClickBackupAndRestoreEngine` & `MigrationVaultCipher` (`migration_and_backup.py`, `crypto_and_archive.py`) | Supports 11 backup modes (including `encrypted_complete_backup`, `incremental_backup`, and `pre_update_restore_point`), verifies every file and checksum before reporting success, enforces PBKDF2-HMAC-SHA256 + AES-256-GCM passphrase encryption for credential vaults, blocks tar path traversal/symlinks/special files, creates pre-restore backups with one-call `rollback_restore()`, and logs every operation in `migration_audit_records`. |
